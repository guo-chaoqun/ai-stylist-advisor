## 二、问题与洞察

用户网购最大的痛点是**"看不到上身效果不敢买"**。AI 穿搭 + 试穿正是解法。

**行业验证**：项目开发期间，淘宝正式上线虚拟试穿功能，验证了方向是行业共识。

我选择不同于大厂的路线：
- **大厂**：平台全包，体验最好但成本最高
- **我**：轻量赋能，先做透搭配质量，图片生成交给用户自助以控成本

> 从 0 到 1 阶段，先做透核心价值，再加强展示层，是更务实的路径。

## 三、关键产品决策

**不是做了什么，而是为什么这么做。** 以下决策都来自实测数据与明确选型。

### 决策 ① 混合架构 — 一半规则，一半 AI

▸ 穿搭既要"懂"（颜色/体型/场合是确定性规则），又要"审美"（风格建议是创造性表达）。

| 方案 | 问题 |
|------|------|
| **全 AI 生成** | 确定性的事容易错、会幻觉、又慢又贵 |
| **混合架构 ✓** | 规则管确定性（质量保底、成本≈0），AI 管创造性（上限更高） |

**事后校验路线**：LLM 生成 → 确定性规则检查 → 不合格打回。

### 决策 ② 用量感替代年龄 — 隐私与可信推荐

▸ 穿搭要知道"成熟度"，但直接问年龄太冒犯、也不准。

- 用**身高派生出量感三档**（小/中/大），不收取敏感信息
- 体重不参与（避免身材焦虑）
- 量感**只做软消费**（排序加权），不做硬门槛
- 依据 ACM 可信推荐研究：勿让用户因敏感特征被"不公平对待"

### 决策 ③ 分层生成 — 不一口气给完

▸ 一次生成完整方案要 60s+，用户等得焦虑。

- 首调：快出核心方案（3967→3093 token，耗时 **22.08s→15.73s，-29%**）
- 二调：按需补充选购指南等细节
- 用户全程有掌控感，也符合 IKEA Effect

### 决策 ④ 试穿选型 — 商业 API 而非自建开源

| 维度 | 自建 (IDM-VTON) | 商业 API ✓ |
|------|:---:|:---:|
| 成本 | $209–2952/月 GPU | ≈0.15 元/张，按量 |
| 周期 | 2–4 周 | 1–2 天 |
| 许可证 | ⚠️ 非商用 | ✅ 商业授权 |

> 技术选型不是选"最好的"，是选"当前阶段最合适的"。

## 五、质量工程方法：AI 不回滚靠什么

> AI 生成的内容是概率性的，标准答案写不死，传统断言很难直接套用。这个项目把客服评测项目沉淀的方法迁移过来，回答两个问题：**主观的穿搭审美怎么变成可执行的评分标准？概率性的 AI 输出怎么保证持续迭代不回滚？**

### 5.1 把主观审美变成评分标准：审美七维 Rubric

"好不好看"无法直接打分，先把它拆成可独立观察、可写锚点的维度，每个维度 1-5 分、写明 1/3/5 分的具体表现：

1. **色彩和谐**：色相调和角度、明度/彩度对比（与标准色相关系对齐）
2. **廓形平衡**：上下装松紧/量感对比是否成立（上松下紧、外长内短）
3. **身形扬长避短**：是否针对自报体型做腰线、遮挡、视觉重心处理
4. **场合契合**：通勤/约会/婚礼等 TPO 着装规范匹配度
5. **风格统一度**：正式度、材质、年代感、装饰度是否互相冲突
6. **层次与完整度**：里-中-外层次是否真实、季节覆盖是否完整
7. **组合逻辑**：每件单品能否说清"为什么出现在这套里"

> SOP 化要点：维度定义 + 1/3/5 分锚点 + 每档正反例图 + 标注试标校准（重合样本算 Cohen's Kappa / Fleiss' Kappa，≥0.8 锁定标准、≥0.85 才放量）。能确定性计算的（色彩角度、温度适配）归规则层，审美语义判分才交给模型——不是所有维度都迷信大模型。

### 5.2 LLM 裁判实证：我抓到了它怎么"骗人"

我用大模型给两套搭配做审美对比评审，并用双序交换等探针检验裁判自身的可靠性，得到一个**有边界的否定结论**（通用对话模型在审美维度上当前不可靠），三条独立证据：

- **位置偏置 87.5%**：8 次调用 7 次选位置在左边的答案；双序交换后同一文本得到互相否定的描述——"判位压倒了内容"
- **量表违规**：要求打 1-5 分，4 对里 2 对打出 8、9 分，分数直接失效
- **裕度不足**：4 对里 3 对两套方案总分差 ≤1 分（满分 50），裁判根本没有分辨力

第二版改成"左右各自独立打分再求和"后 tie 率 100%→25%，但校准硬门仍未过。结论：不再靠"换措辞"修，重启需换范式——**用人类偏好数据训练的专用模型（ImageReward / HPSv2 / VIEScore）或多判官集成，且自动分必须与人工 MOS 算等级相关，不达标只作初筛不作判决**。这三项探针（位置偏置/量表遵从/裕度分布）后来成为我另一个文本评测项目裁判设计的标配。

### 5.3 质量门禁与工程化

- **黄金集回归（34 例）**：历史上出过问题的场景全部沉淀为固定用例，每次改动重跑——防止同一个错犯第二次
- **627 条自动化断言（单元 + 集成 + E2E）**：分层覆盖，出问题能快速定位到具体层级
- **变异测试（60+ 故障注入）**：故意制造错误，验证"断言该红的会红"——证明测试本身有效，而不是摆设
- **对照评测 + 盲评**：每次改生成 Prompt，新旧两版在同一批输入上的输出隐去版本标识后盲评，避免"新版一定更好"的心理暗示
- **导购词三维代理指标**：关键词可搜性 / care 可执行性 / pairing 具体性，全部脚本可数，并以阳/阴性对照验证判据"不会永远绿"
- **自我质疑式迭代**：设计综合复盘时刻意拿数据重验 v2 的核心结论，3 个结论推翻了 2.5 个——最关键的一个否定了"输入侧要建服装词表"，避免把整个开发优先级排反
- **分层门禁**：日常快检 → 合并前回归 → 发布前全量，问题在最便宜的阶段被拦住

> 📦 **同一套评测方法论的文本侧完整版**（505 条评测集、规则+LLM 裁判双通道、43 条 badcase 八类归因、McNemar p=0.02 验证、185 条回归集）见另一个项目：[电商智能客服 · AI 评测体系从 0 到 1](https://github.com/guo-chaoqun/ecommerce-ai-customer-service)。两个项目共同构成"文本 + 多模态"的完整评测实践。
